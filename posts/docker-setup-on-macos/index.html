Run Docker on macOS with Colima

November 1, 2025 · 3 min · 427 words · Matthew G | Suggest Changes

在企业环境中，Docker Desktop 可能受到授权、策略或系统配置限制，导致 Docker daemon 无法正常启动。即使日常的镜像构建通常由 CI/CD 流水线完成，本地开发、调试和学习时仍然需要一个可用的 Docker runtime。

本文介绍两种在 macOS 上运行 Docker 的方案：

  • Rancher Desktop：提供图形界面，可同时管理容器运行时和本地 Kubernetes，适合希望开箱即用、可视化配置的用户。
  • Colima：基于 Lima 的轻量命令行方案，适合偏好 CLI、希望控制资源占用的用户。

两者都会在 Linux 虚拟机中运行容器服务，并让 macOS 上的 Docker CLI 连接该服务。日常只需要使用 Docker 时，二选一即可，不建议同时启动，避免 Docker context 和资源占用相互干扰。

Choose a Runtime#

方案更适合Docker CLIKubernetes操作方式
Rancher Desktop希望通过界面管理配置和状态选择 Moby 后可用内置，可关闭GUI + rdctl
Colima偏好轻量、脚本化的本地环境可用可选CLI

如果希望获得接近 Docker Desktop 的桌面体验，可以优先选择 Rancher Desktop；如果只需要一个轻量 Docker daemon，可以继续使用 Colima。

Rancher Desktop#

Rancher Desktop 是一个开源桌面应用，支持 macOS 的 Intel 和 Apple Silicon 设备。它提供两种容器引擎：

  • dockerd (moby)：提供 Docker API，使用 docker 和 docker compose。
  • containerd：使用 nerdctl，不会提供完全相同的 Docker API。

本文后续示例都使用 Docker CLI，因此安装后需要在 Preferences → Container Engine 中选择 Moby (dockerd)。

Install Rancher Desktop#

官方推荐从 Rancher Desktop Releases 下载与芯片架构匹配的 DMG 文件，然后将应用拖入 Applications 目录。首次启动会初始化 Linux 虚拟机并下载所需组件，耗时取决于网络情况。

如果不需要本地 Kubernetes，可以在设置中关闭 Kubernetes，以减少启动时间和资源占用。然后确认容器引擎为 Moby，也可以使用命令行设置：

rdctl set --container-engine.name=moby

Rancher Desktop 启动完成后，检查 Docker context 和 daemon：

docker context ls
docker context use rancher-desktop
docker info
docker run --rm hello-world

正常情况下，Rancher Desktop 会自动创建并切换到 rancher-desktop context。如果当前 context 仍指向 Colima 或其他运行时，可以手动切换。

Docker Compose 也可以直接使用：

docker compose version
docker compose up -d
docker compose down

Manage Rancher Desktop#

除了图形界面，也可以使用 rdctl 查看状态和调整配置：

rdctl list-settings
rdctl shutdown

切换容器引擎后，原引擎中的镜像和容器不会出现在新引擎中。如果依赖 Docker API、Testcontainers 或 VS Code Dev Containers，应保持使用 Moby。

Colima#

Install Colima#

首先安装 Docker CLI、Colima 和 Docker Compose：

brew install docker colima docker-compose

这里安装的是 Docker 客户端，而不是 Docker Desktop。Colima 启动后会自动配置 Docker context，通常不需要额外设置 DOCKER_HOST。

Start Colima#

使用 Docker runtime 启动 Colima：

colima start --runtime docker --cpu 4 --memory 6 --disk 60

参数分别表示 CPU 核数、内存大小和虚拟磁盘大小。第一次启动时，Colima 会创建并初始化虚拟机，可能需要一些时间。

启动完成后，先确认 Docker daemon 是否可用：

docker info
docker run --rm hello-world

如果 hello-world 能够正常运行，说明 Docker CLI、Colima 和 Docker daemon 已经连通。

常用的运行状态命令如下：

colima status
colima stop

Lima and Colima#

Colima 会使用 Lima 管理底层 Linux 虚拟机。大多数 Docker 日常操作都应该通过 colima 和 docker 命令完成，只有在排查虚拟机或挂载问题时才需要直接使用 Lima 工具。

# 查看 Lima 实例
limactl list

# 进入 Colima 对应的 Lima 虚拟机
limactl shell colima

Colima 的默认配置可以通过下面的命令编辑：

colima start --edit

例如，可以在配置中声明一个可写挂载目录：

mounts:
  - location: ~/Projects
    writable: true

Container Networking#

一个常见问题是：宿主机上的服务可以访问，但容器中的程序无法连接宿主机上的 MySQL、Redis 等服务。

原因在于 Rancher Desktop 和 Colima 的容器服务都运行在 Linux 虚拟机中。容器中的 localhost 指向容器自身，而不是 macOS 宿主机，因此下面这样的配置在容器中通常无法连接宿主机服务：

[mysql]
host = "localhost"
port = 3306
user = "root"
password = "password"

在这两种运行时中，可以优先使用 host.docker.internal 访问宿主机：

[mysql]
host = "host.docker.internal"
port = 3306
user = "root"
password = "password"

需要注意的是，宿主机上的服务必须允许来自虚拟机网络的连接；如果服务只监听 127.0.0.1，仍然可能无法访问。遇到连接问题时，还应确认当前 Docker context 指向实际正在运行的 Rancher Desktop 或 Colima。

Inject Configuration#

更适合容器化应用的做法是：让环境变量覆盖配置文件中的默认值。以 Golang 的 Viper 为例：

viper.AutomaticEnv()
viper.SetEnvKeyReplacer(strings.NewReplacer(".", "_"))

这样，配置文件中的 mysql.host 就可以通过 MYSQL_HOST 环境变量覆盖。运行容器时，可以直接传入环境变量：

docker run \
  -e MYSQL_HOST=host.docker.internal \
  -e MYSQL_PORT=3306 \
  -e MYSQL_USER=root \
  -e MYSQL_PASSWORD=password \
  my-service

当环境变量较多时，使用 --env-file 会更方便：

docker run --env-file .env my-service

.env 文件可以写成：

MYSQL_HOST=host.docker.internal
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=password

不要把包含真实密码的 .env 文件提交到代码仓库。可以提交一个 .env.example，只保留变量名和示例值。

Summary#

Rancher Desktop 和 Colima 都能在不依赖 Docker Desktop 的情况下，为 macOS 提供 Docker 环境。Rancher Desktop 更适合希望使用图形界面、Docker Compose 或本地 Kubernetes 的用户；Colima 更轻量，也更适合命令行和自动化工作流。

无论选择哪一种方案，都要先确认 Docker context 指向正确的运行时，并理解容器、Linux 虚拟机与 macOS 宿主机之间的网络边界。这样在处理宿主机服务访问、配置注入和容器调试时会更加直观。
